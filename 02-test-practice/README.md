# 测试练习

目标：用**真实系统**完整走一遍测试流程，产出一份能直接拿去面试的用例和缺陷报告。

## 计划（第 3—4 周）

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 1. 选对象 | 学校教务 / 图书馆系统，或一个公开可测的网站 | 一句话说明测什么 |
| 2. 拆功能 | 登录、查询、提交表单、异常输入、权限 | 功能清单 |
| 3. 写用例 | 等价类 + 边界值 + 场景法，≥ 15 条 | `cases/` 下的用例文档 |
| 4. 执行 | 逐条执行，记录现象 | 执行结果 |
| 5. 提缺陷 | 现象 / 复现步骤 / 预期 vs 实际 / 日志 | `reports/` 下的缺陷报告 |
| 6. 写总结 | 发现几个问题、哪类问题最多 | 一页测试总结 |

## 目录

```
02-test-practice/
├── cases/      # 测试用例文档
├── reports/    # 缺陷报告
├── scripts/    # 接口测试脚本（Postman 导出 / pytest）
└── README.md
```

## 我要练的三件事

1. **用例设计**：不是"把页面点一遍"，而是能说清每条用例覆盖了哪个等价类、哪个边界
2. **缺陷描述**：让别人照着我的步骤能 100% 复现
3. **接口测试**：用 Postman 调通，再用 pytest 写成可重复运行的脚本

## 边界

- 只测**自己有权限**测试的系统（学校开放给学生使用的部分）
- 不做破坏性操作（不压测、不删数据、不尝试越权）
- 不采集、不公开任何真实用户数据；截图打码
