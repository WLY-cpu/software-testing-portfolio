# 缺陷报告模板

一份好的缺陷报告，标准只有一条：**开发照着我的步骤，能 100% 复现**。

## 缺陷单

| 项目 | 内容 |
|---|---|
| 缺陷编号 | BUG-2026-11-001 |
| 标题 | 例：登录页输入超长用户名后点击登录，页面无响应 |
| 发现人 | 王乐阳 |
| 发现时间 | 2026-11-xx 14:30 |
| 被测系统 / 版本 | 例：教务系统 学生端 v2.3 |
| 测试环境 | 例：Chrome 120 / Windows 11 / 校园网 |
| 严重程度 | 致命 / 严重 / 一般 / 轻微 |
| 优先级 | 高 / 中 / 低 |
| 缺陷类型 | 功能 / 界面 / 兼容性 / 性能 / 安全 |

## 复现步骤（最关键的部分）

1. 打开登录页 `https://xxx/login`
2. 用户名输入 200 个字符：`aaaaaaaa...`（见附件 testdata.txt）
3. 密码输入任意合法值
4. 点击"登录"按钮

**复现概率**：5 次 / 5 次

## 预期结果

提示"用户名长度不能超过 20 位"，并停留在登录页。

## 实际结果

页面无任何提示，按钮置灰 3 秒后恢复，控制台报错：
```
Uncaught TypeError: Cannot read properties of undefined (reading 'length')
  at validate (login.js:42)
```

## 写缺陷的四个坑

| 坑 | 反例 | 正确写法 |
|---|---|---|
| 只说现象不说条件 | "登录有问题" | "输入超长用户名时……" |
| 混淆预期和实际 | "应该提示错误" | 预期："提示长度超限"；实际："无提示" |
| 步骤不可复现 | "随便点点就崩了" | 写清 URL、数据、操作顺序、复现概率 |
| 不带证据 | 只写结论 | 附截图 + 控制台报错 |
